# Lessons

What this project's past changes taught us. Read all of this before changing an API, a format or an
agreed behaviour here. For the full story of a line, find the entry with the same date and name in
`lessons-full.md`.

When one has to change, add the full entry to `lessons-full.md` and one line here, newest last, in the
same commit as the change. Keep this file under 20 KB: at the cap, merge lines before adding.

- **2026-10-29 TSVZ: strict writes**: a default may be lossy on read (show what is there) but never on write; refuse, and let the caller ask for the loss.
- **2026-10-29 TSVZ: pointer x-delimiter escaping**: a field that can hold any byte needs an escaping rule in the format, and a test of each store kind through the real path.
- **2026-10-29 TSVZ: rewrite order**: an in-place rewrite should pass only through states a reader can live with; write over, then cut, and make readers notice a cut short (every codec, not only the one that raises).
- **2026-10-29 TSVZ: last chance at close**: when a message promises what happens next, compute that promise from the same state that schedules it. Check every throttle and dedupe at the point of no return (close, exit, a Ctrl-C in either), because that is where "later" stops existing.
- **2026-11-01 TSVZ 5.1: a legacy scrub that writes nothing fails**: when two dialects share a command, give both one result shape (rows, done) from the library, and let the CLI and handler map that one value; a hard-coded `return True` in a caller is a result nobody computed.
- **2026-11-01 TSVZ 5.1: scrubTabularFile(lastLineOnly=True) of a .tsv is a read**: a function built as "read, then write back" must take only read options that keep the result a whole store; an option that changes the result's shape either makes it a pure read or is refused, never written back.
- **2026-11-01 TSVZ 5.1: a legacy scrub keeps the file's #_defaults_# lines**: a compaction must write back everything that changes how the rows read, not only the rows, and put it where it reads the same; test a compaction by reading before and after with every reader, not only by comparing to an expected byte layout.
- **2026-11-03 TSVZ 5.2: --x-header makes line 1 the header for every CLI operation**: a fact about a file that changes how every row reads (its header, its width, its defaults) is decided in one place that every operation goes through, from the file, never from which command is running, by an exact rule (a loose match turns data into structure). Test it by running every operation on the same file and checking that the rewrite keeps exactly what the reads showed, and that the rewritten file reads the same way under the rule again.
- **2026-11-04 TSVZ 5.3: readers lock, and the file lock is split into byte ranges**: when processes share a file that is rewritten in place, readers take part in the lock from the first version. Treat the lock layout (who locks which range, and who owns the lock) as an API, with older versions' locks in its compatibility table. Old whole-file locks still exclude every new range, so the change needed no flag day. a reader/writer lock built from kernel locks needs a turnstile against writer starvation; check fairness before arguing that reads "drain".
- **2026-11-04 TSVZ 5.5: a legacy row is its own cells, and a compaction only drops lines**: a reader may pad or validate but never drop data; a compaction removes what no reader needs and changes nothing it keeps, so what every reader sees is kept by construction instead of by rules that rebuild it. Test a compaction differentially: old and new readers, both strictnesses and other arguments, on the same bytes before and after. a maintenance write (compaction) is something the caller asks for; defaults should not write. a change that is not written when made needs state to remember it, and that state is where the bugs live. Say it in the form the file already has, or put it in the one queue every other write goes through, so reads and retries keep it with no extra part. And when a fuzzer's invariant keeps flagging what the design allows ("reopen == memory" against defaults the program changed), restate it as what the operator relies on (the rewrite changes nothing the same reader reads) before patching code to it.
- **2026-11-05 TSVZ 5.5: correctColumnNum= on a TSVZed no longer pads**: an argument that restates a fact of the file the library can read for itself (its width) is a hint at best; read the file, and never let the hint rewrite it.
- **2026-11-06 TSVZ 5.6: a reader works on its own copy of defaults**: an argument is an input: work on a copy, and give what the read found its own way out. Before making two entry points agree through one normaliser, check what each form means to each.
- **2026-11-06 TSVZ 5.6: rewrite(force=True) always writes**: a flag named for doing something does it. A state flag may schedule automatic work; it never gates a call that asked for the work.
- **2026-11-06 TSVZ 5.6: a delete is the same act through every door**: when a rule depends on a fact of the file, every writer asks the file, through one function; fixing the one writer a test found leaves the others saying the opposite.
- **2026-11-06 TSVZ 5.6: a rewrite widens line 1 to the header the program gives**: when a rule added to stop one bad case also stops a good one, separate them by an exact test rather than by forbidding the operation; and a fact that changes how every row reads moves with everything that depends on it.
- **2026-11-06 TSVZ 5.6: a delete reads the file under the lock it writes under**: a decision made on a read taken before the lock needs a retry, a stamp and a failure path; read through the lock and the failure mode is gone.
- **2026-11-06 TSVZ 5.6: a strict store follows a widening header, and a clean store takes in what others wrote**: refusing a thing by its looks stops the good case that looks the same; compare exactly. A flag that turns a check off must not turn off the guard against deleting what the program never held.
- **2026-11-06 TSVZ 5.6: a file is compacted at its own width, never the store's**: what a line means depends on the width the file reads at, and a store's defaults can name another width than the file has; a rewrite that carries out deletions at the store's width deletes rows the file's other readers see.
- **2026-11-06 TSVZ 5.6: a rule that tells two lines apart is one function, exact**: the check that accepts a widened line 1 and the code that writes one must be the same rule; a containment test in one and an equality in the other let a line that only resembles the header pass for it, and a strict store that followed a widening read none of its rows.
- **2026-11-06 TSVZ: a command that differs from another only in case is a script file, not an entry point**: a command name is also a config key to the tools that install it. pip 9 (stock on EL7 and EL8) reads `entry_points.txt` case-folded and fails to upgrade or uninstall a package with two commands that differ only in case; keep one as the entry point and ship the other as a `scripts=` file, and test an install with the oldest platform's stock pip.
- **2026-11-06 TSVZ 5.6: a file's width is the file's, asked of one function**: keep "what does this reader make of the file" apart from "what does the file say", and let any write that can lose a line ask only the second. When a guard has to be told to ignore an argument, the argument should not have reached it.
- **2026-11-06 TSVZ 5.7: a daemon thread stays out of the streams at the exit, and a library says nothing unasked**: anything a daemon thread does at the moment of exit must be safe to be frozen in: a lock taken there is held for ever. Close the door at the exit, wait for those inside with a bound, and let what comes after use a path with no lock; the door goes where every print passes, not at the one message that showed the bug.
- **2026-11-07 TSVZ 5.8: a delete keeps every line that sets a reader's count in its place**: when one fact that every reader takes from one place has to survive a removal, keep the place and change what it holds; moving a neighbour into it changes what every reader of the neighbour, and of the lines it passes, sees.
- **2026-11-08 TSVZ 5.09: a delete's commit is a delete, not a compaction** (REVERSED the same day by the 5.10 line below: the commit compacts again): when one operation is carried out by another's machinery, a door that does more than the others is the one to check first, but the fix is the machinery made right for every reader, not the step taken out of that door.
- **2026-11-08 TSVZ 5.10: a compaction keeps what every count the file is read at takes**: when a file is read at more than one count, a maintenance step keeps what each of those readers takes and changes a line only where all agree; a step right for only one reader is made right for every reader, not removed from the door where the loss showed (it may be what pays for something else: 5.9's commit without it grew files quadratically); a condition checked at one count must hold at every count a reader can take (a reader given defaults reads at their count, and a reader given none is another reader, planned at the count it then reads at).
- **2026-11-09 TSVZ 5.11: a rule follows its premise to the doors where it holds, and an old reader is modelled as it is**: a rule bought with one reader's cost applies only in the doors where its premise holds (who the deleting program is, as that door reads the file); model an old reader's state as it keeps it (per-cell defaults, not a flag), and plan every reader the caller names (an explicit count), not only those the file implies.
- **2026-11-09 TSVZ 5.12: a choice ranked by one invariant is checked against every invariant, and a reader joins a plan only where it can differ**: rank candidates by every invariant readers rely on (rows, cells and order), so one that keeps them all goes first even when it came later; plan each reader at the count it reads at, and add one only where an exact test says it can read otherwise (a copy of a planned reader costs time and keeps lines).
- **2026-11-09 TSVZ 5.13: shutdownEvent is a flag that holds no lock, and no lock another thread waits for is left to a Ctrl-C**: in Python a Ctrl-C can land between almost any two bytecodes of the main thread, even inside threading's own code, and skip a `with` statement's exit (bpo-29988): never let another thread wait for a lock the main thread holds across Python code. Signal with a flag and a lock per waiter, hand writes to the thread that owns the file, and where a lock must be shared, use one that knows its holder: the holder drops a hold it finds itself in where it can be in no section, the method a Ctrl-C goes up through drops it too, and the section's exit accepts that a signal handler inside it dropped it first (a handler runs inside whatever the main thread was doing). Work moved to a thread the exit waits for makes the exit wait for it: the exit must tell a read from a write. Raise the interrupt at every step in turn to find the places, as a real signal can land (3.12+: `sys.monitoring`; up to 3.11: settrace's `opcode` events only, as 3.9 loses a raise at a `line` event an opcode event follows; skip 3.11+'s `NOT_TAKEN` and `NOP`, which the exception table leaves out), keeping no exception object (its traceback holds the cut write's open file), and measure the operator's cases (a Ctrl-C ending a write loop, caught and not; one during a big load; a handler that uses the store).
