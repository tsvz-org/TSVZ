## The rules being built (settled; do not redesign)

### R: reading (one helper, every reader)

`_fitRow(cells, width)` (new, module level): when `width > 0` and `len(cells) < width`, pad with `''` to `width`; when
`len(cells) > width`, drop only the empty cells at the end past `width` (`a\t1\t\t` at W 2 is `[a, 1]`;
`a\t1\t2` stays `[a, 1, 2]`); never drop a non-empty cell. Returns a list. It replaces every cut in the module (5.4 has
five, all `[:n]` slices: `_processLine` line ~1725, `_legacyFormatRows` ~2422, `_legacyScrub` ~2749 (removed with
the old scrub), `TSVZed._shapeRow` ~5313, `TSVZedLite.__setitem__` ~7242). After this change
`grep -n "\[:correctColumnNum\]\|\[:columns\]\|\[:self.correctColumnNum\]" TSVZ.py` finds nothing.

- R1, `_processLine`, the `len(lineCache) != correctColumnNum` branch (not strict, or strict with non-empty defaults
  in effect): `lineCache = _fitRow(lineCache, correctColumnNum)`. The branch for a lone key or a line with no
  non-empty value (`len == 1 or not any(cells[1:])`) is unchanged: at W 1 it stores the line as is (`b\t` stays
  `[b, '']`, as 5.4: the views fuzzer must show no narrower row).
- R4, `_processLine`, after the fit and before the defaults fill: a `#_defaults_#` line shorter than the defaults in
  effect is padded with `''` to their length, so the fill takes the cells it lacks from the defaults before it
  (protoH lines 35-36 of the diff).
- R2, R3, R5 unchanged: W is decided as today (header that line 1 holds, else caller defaults of 2+ cells, else the
  first keyed line); deletion is decided on the line as written; strict drops a line of another width unless defaults
  with a non-empty cell are in effect.

### W: writes pad only (Q5)

- `_legacyFormatRows` (so `appendTabularFile`, `appendLinesTabularFile`, `tsvz set`/`append` and the handler, which
  call it): rows are fitted with `_fitRow(line, correctColumnNum)`. Its third return value (`columns`) was used only
  by the old scrub: drop it and fold `_legacyFormatRows` into `_legacyFormatPayload` (keep the name
  `_legacyFormatPayload`; update its callers, and the test helper `_append_between_read_and_write`, which patches it).
- `TSVZed._shapeRow` (set path): a row of another width is refused when `self.strict` (unchanged), else
  `value = _fitRow(value, columns)`.
- `TSVZedLite.__setitem__`: the same (strict refuses, else `_fitRow`). This extends Q5 to `TSVZedLite`; listed in
  Calls to confirm.

### L: `TSVZed` loads and reloads

- `TSVZed._shapeRow(key, value, columns, defaults, load=False)`. With `load=True` (rows a read hands over): right-strip
  the key and every cell (as 5.4), put the key first when missing, and return `(value, columns if columns > 0 else
  len(value))`. No fit and no defaults fill: the read did both, as the reader does them. This makes `TSVZed` and
  `readTabularFile` agree on 1-column files with `#_defaults_#` lines (design 7.3; `b\t` is `[b, '']` for both).
  `_TSVZedLoad._change` calls it with `load=True`.
- R6: `_TSVZedLoad._change` no longer turns a lone-key row into a delete (`if self.columns != 1 and len(value) == 1:
  return key, None` goes). A read hands a lone key over as a row only at W 1; deletions reach the load through
  `__delitem__`. `_TSVZedLoad.replay` (queued rows) is unchanged. `_TSVZedMerge` inherits both.
- Q-D5: `TSVZed.__init__` keeps `self._givenColumns = correctColumnNum` and `self._givenDefaults = list(self.defaults)`
  (legacy only). `setDefaults()` on a constructed legacy store also sets `_givenDefaults` (the program's defaults are
  the ones it gave last). `_readFrom` loads into `_TSVZedLoad(self, self._givenColumns, list(self._givenDefaults))`
  (5.4: `self.correctColumnNum, list(self.defaults)`). `_applyAppended` (the incremental follow) keeps memory's
  current column count and defaults: it continues a read, it does not start one.
- Column count after a whole read: `_readFrom` keeps the W that `_legacyReadLoop` returned. The header branch is
  unchanged (`len(self.header)` when a header is given and checked); otherwise `self.correctColumnNum` is that W when
  it is above 0, else `len(first row)` when memory holds a row (queued rows replayed), else -1. 5.4 took the first
  memory row's length, which R1 can make wider than W. `_applyAppended`'s `correctColumnNum == -1` fallback takes the
  W its `_legacyReadLoop` returned the same way.

### C: the compaction (`_legacyCompact`, one function for the scrub and the `TSVZed` rewrite)

Pure functions over a list of raw lines (bytes, without their newline). They never encode text, so they never raise
`TSVZEncodeError`, and every line they output is a line of the input, byte for byte, except one emptied line (below),
which is built from the input's own bytes.

`_legacyLineKind(text, width, strictActive, delimiter)` -> `(kind, key, ncells, strictTakes)`, the classification
`_processLine` makes, without changing anything:

1. `line = text.strip('\x00').rstrip('\r\n')`; empty, or `#` not followed by `_defaults_#` -> `('skip', None, 0, False)`.
2. `cells = _unsanitize(line.split(delimiter), delimiter)`; no cell or an empty first cell -> skip.
3. One cell, or no non-empty cell after the first: `#_defaults_#` -> `'reset'`; else at `width == 1` -> `'row'`; else
   `'delete'`. `strictTakes` is True for all three (a strict read applies them whatever their width).
4. Otherwise `'defaults'` for `#_defaults_#`, else `'row'`; `strictTakes = (len(cells) == width) or strictActive`.

`_legacyCompactOnce(raw, width, consumed, defaults, delimiter, encoding, matched)` (`width`: the W of the caller's
reader, -1 when it is taken from the first keyed line; `consumed`: the reader takes line 1 for its header, i.e. a
header is given and checked; `matched`: line 1 holds that header, `_headerMatches`; `defaults`: the caller's):

`after0`: the first index >= 1 whose line `_legacyLineKind(..., width=1, strictActive=False, ...)` does not skip (the
first keyed line after line 1, for any reader). `line0Keyed`: line 0 does not skip by the same test. Both are found
before the main loop (a forward scan that stops at the first hit). `P = {0, after0}` (without `after0` when there is
none) are the indexes that may be protected.

```
decode each line as it is classified (encoding or 'utf8', errors='replace'); keep no list of decoded lines
strictActive = len(defaults) > 1 and any(defaults[1:])
live = OrderedDict() # key -> [first, last, firstTaken, lastTaken, firstN, lastN, firstTakes, lastTakes]
                     #        for its lines since its last deletion (N: cell count; Takes: a strict reader takes it)
pinfo = {}           # j in P that is a row -> (key, ncells)
killer = {}          # j in P whose key died -> index of the deletion that ended it
lastDelete = {}      # key -> index of its last deletion line
boundaries = []      # indexes of #_defaults_# lines (defaults and reset), in order
firstKeyed = None
for i, line in enumerate(raw):
    if i == 0 and consumed: continue
    kind, key, n, takes = _legacyLineKind(decode(line), width, strictActive, delimiter)
    if kind == 'skip': continue
    if width == -1:                        # the first keyed line sets W, as _processLine does
        width = len(defaults) if len(defaults) > 1 else n
        kind, key, n, takes = _legacyLineKind(decode(line), width, strictActive, delimiter)
    if firstKeyed is None: firstKeyed = i
    if kind in ('defaults', 'reset'):
        boundaries.append(i)
        strictActive = False if kind == 'reset' else (True if takes else strictActive)
    elif kind == 'delete':
        rec = live.pop(key, None)
        if rec is not None:
            for j in P: if j in pinfo and pinfo[j][0] == key and j >= rec[0]: killer[j] = i   # j was in this segment
        lastDelete[key] = i
    else:                                  # a row
        if i in P: pinfo[i] = (key, n)
        rec = live.get(key)
        if rec is None: live[key] = [i, i, i if takes else None, i if takes else None, n, n, takes, takes]
        else:
            rec[1], rec[5], rec[7] = i, n, takes
            if takes: rec[2] = i if rec[2] is None else rec[2]; rec[3] = i
```

Only per-key records and at most two protected entries are held; no per-line list.

Kept (a set of indexes, plus `content`, a dict index -> replacement bytes):

1. Line 0 (when `raw` is not empty), and every index in `boundaries`.
2. For each live key's record: keep `first`. If `first != last`:
   - substitute when no boundary lies between `first` and `last` (`bisect_right(boundaries, first) ==
     bisect_left(boundaries, last)`), a strict reader takes both (`firstTakes and lastTakes`), `first != 0`, and
     `first` is neither `firstKeyed` nor `after0` or `firstN == lastN`: `content[first] = raw[last]` (the last line's
     bytes at the first line's place: the key is one line);
   - else keep `last`, and keep `firstTaken` and `lastTaken` when they are not None (a strict reader's place and value).
3. Protected lines: `0`, and `after0` when it exists and (`not line0Keyed` or (`consumed` and not `matched`)). Keep
   each. When a protected line `j` belongs to a key that died (`j in killer`):
   - `j != 0`, `pinfo[j]`'s ncells > 1, and the delimiter is not NUL: `content[j] =` the line's raw key (the bytes of
     `raw[j].strip(b'\x00')` up to the first delimiter byte sequence) followed by `ncells - 1` delimiters: an emptied
     line, a deletion as wide as the line was, so W stays and the key stays dead; the deletion `killer[j]` is not kept;
   - otherwise (line 0, a one-cell line, or `.nsv`, whose readers strip trailing NULs so an emptied line would read one
     cell wide): keep `killer[j]` too.
4. When `consumed and line0Keyed and not matched`: line 0 is a row to a reader given no header; when its key (as
   classified at the caller's width) is not live and has a deletion, keep `lastDelete[key0]`.

Output: `[content.get(i, raw[i]) for i in sorted(kept)]`.

`_legacyCompact(...)`: run `_legacyCompactOnce` until its output equals its input, at most 4 passes; after the 4th the
last output is used. Bound: every pass keeps what each reader takes (it only drops lines, or empties a dead key's
protected line), so stopping early is less compact, never wrong; emptying one line can make one more line droppable,
which is why it repeats. The fuzzer saw no case needing more than the prototype's 4 (invariant 3, idempotence: 0
failures). Task 3 adds a test that a fixed point is reached within 3 passes on the fuzz corpus and the byte examples,
so the bound has margin.

`_legacyWidthOf(line0, header, consumed, defaults, encoding, delimiter)`: `len(header)` when `consumed` and
`_headerMatches(header, line0)`; else `len(defaults)` when it has 2+ cells; else -1. (The W a `TSVZed`'s own whole
read takes: `_readFrom` passes -1 to `_legacyReadHeader`.) The scrub does not need it: its one read returns W.

### S: the scrub (`_legacyScrub`): one read, then the compaction

Per attempt (up to `_SPEC_REWRITE_ATTEMPTS`, as 5.4):

1. `taskDic` reset as now; `stamp = _specFileStamp(fileName)` before the read.
2. `_verifyFileExistence(createIfNotExist=...)` as `readTabularFile` does; missing and not made -> return `(taskDic,
   True)`. A file that holds nothing (`_fileHoldsNothing`) -> `(taskDic, True)`, as 5.4.
3. `_legacyScrubRead(...)` (new; tests hook it, so keep the name): opens the file once, under `_readLock`, through
   `openFileAsCompressed`, wraps it in `_RawTap` (below), and runs `_legacyReadHeader` and `_legacyReadLoop` exactly as
   `readTabularFile` does (same reporter, warnings, damage notes, strict drops). Returns `(raw, W)`: every line the read
   took, as bytes without the newline, and the W the read ended with. The view is `taskDic`, filled by that same read.
   So the view and the compaction come from the same bytes (5.4's single-read property; protoH read twice, which broke
   the "row appended between read and write" tests).
4. `lines = _legacyCompact(raw, W, consumed, givenDefaults, dlm, encoding, matched)` with `consumed = any(header) and
   verifyHeader` and `matched = consumed and raw and _headerMatches(header, raw[0] decoded)`.
5. A header given with `verifyHeader=False`: when line 1 is not that header (`_isHeaderLine`), the header line goes
   first (as 5.4 and protoH; it is the only text a scrub encodes, so the only `TSVZEncodeError` it can raise).
6. `raw` empty because the read met damage before line 1 (a `.gz` holding plain text, a first member cut short): the
   output is the header given, if any, else nothing, as 5.4 made such a file again
   (`test_legacy_scrub_of_a_gz_file_whose_first_line_cannot_be_decoded_does_not_raise`).
7. `payload = b''.join(line + b'\n' for line in lines)`; `_legacyReplace(fileName, [], False, encoding, dlm, errors,
   payload, expect=stamp)`; None -> next attempt; else `(taskDic, True)`. The scrub writes whenever the file holds
   something, also when nothing is dropped (as 5.4: a compressed file is recompressed, as `scrubTabularFile`'s
   docstring promises; protoH skipped the write, see Calls to confirm).

`_RawTap(f)`: wraps the open binary file; `readline()` and `__next__` hand the line over and append it (newline
taken off) to `self.raw`; `__iter__` returns self; `tell()` delegates. About 15 lines.

Damage (5.4's member reader): the tap records only what the reader handed over, so a member left out, or the bytes
after a stopping damage, are not in `raw`, and the compaction writes what the read took, as 5.4's scrub wrote the rows
it read.

Goes away with the old scrub: `_DefaultsList` (and its four hooks in `_processLine`), `_chainFill`, the `notFirst`
parameter (and its use in `_ServeStore.scrub`, and the comment above it), the scrub's calls of `_legacyKeptHeader`,
`_legacyBeginsBlank` and `_legacyFormatRows`. Remove each function the grep shows unused afterwards
(`_legacyBeginsBlank` very likely; `_legacyKeptHeader` stays for `clearTabularFile`; `_legacyBeginsBlankIn` stays for
`_headerLine`; `_isHeaderLine` stays if anything else uses it).

### H: the `TSVZed` rewrite (the hybrid of Q-D3)

`_snapshotForRewrite(f)` first tries `_compactSnapshot(f)`; None -> 5.4's memory dump, unchanged (R1 rows, header,
defaults line, `_RewriteRows`).

`_compactSnapshot(f)` returns None (memory dump) when any of: `self._damaged`, `self._remake`, `self._dumpNext` (set
by `move_to_end`, and by a delete in a 1-column store, Task 5b), the file is not a regular file or is missing, the file
holds nothing (`_holdsNothing`), or the raw read below meets damage (an exception from the codec stream, or a
`_DamagedStream`). Otherwise, all under the `writeLock` and the REWRITE lock `_writeFileStarted` already holds:

1. **Raw read through `f` only.** `f.flush(); f.seek(0)`; read the lines through `_openStreams(codec, f)` for a
   compressed file, `f` itself for a plain one; `f.seek(0)` after. Never `_readLock`, never an open by name: this
   thread holds the REWRITE lock (a read lock would wait for itself, and `_readLock` skips it only by
   `_heldHere`), and on a `lockf`-fallback host closing any other descriptor of the file drops the write lock.
2. **The queue.** Under `_memLock` take `queued` as now; each queued row (`#` keys left out, `#_defaults_#` kept) is
   encoded as `_commitOnceStarted` encodes an append (`_encodeRow(_sanitize(row, delimiter=...), delimiter, encoding,
   errors, self.header)`) and added after the raw lines: the compaction sees the file as the append will make it. A
   `TSVZEncodeError` puts the queue back (`extendleft(reversed(queued))`) and raises, as 5.4's snapshot does.
3. **Compaction.** `header = self.header if any(self.header) else []`, `consumed = bool(header) and
   self.verifyHeader`, `defaults = self._givenDefaults`, `W = _legacyWidthOf(raw[0] ...)`, `matched` as in S;
   `kept = _legacyCompact(raw, W, consumed, defaults, ...)`. Drop `raw` (`del raw`) once `kept` is made: `kept` shares
   its bytes objects.
4. **What the compacted file says, streamed.** Parse `kept` with `_legacyReadHeader` and `_legacyReadLoop` over
   `_LinesFile(kept)` (below), into `_TSVZedDiff(self, self._givenColumns, list(self._givenDefaults))`, with
   `self.strict`, as `_readFrom` reads a file. `_TSVZedDiff(_TSVZedLoad)` holds no rows: for each change `(key, row)`
   (`_change`, `load=True`) it stores `flags[key] = (row == dict.get(self, key))` (memory looked up without
   `_memLock`: a read of one key; a row replaced meanwhile shows as a difference and is written, which is harmless);
   a delete stores `flags[key] = None`; `__contains__` returns True (as `_TSVZedMerge`). It keeps the W its loop
   returns (`diffWidth`).
5. **The diff, under `_memLock`:** `values = [row for key, row in OrderedDict.items(self) if flags.get(key) is not
   True and not str(key).startswith('#')]` (memory order; a row memory holds that the file does not read the same:
   changed in place, put in memory straight, or a key the file has dead); `gone = [key for key, flag in flags.items()
   if flag is not None and not dict.__contains__(self, key)]` (keys the file has live that memory no longer holds;
   file order).
6. **Deletion lines** for `gone`: `[key] + [''] * (diffWidth - 1)` when `diffWidth > 1`, encoded with `_encodeRow`
   (an unencodable key raises `TSVZEncodeError`: queue back, raise, as 5.4). When `diffWidth == 1` the format cannot
   delete (a lone key is a row there): see Task 5b.
7. **Defaults** (open question Q2, default (a)): when memory's defaults (`self.defaults`, 2+ cells, a non-empty
   one) differ from the defaults the compacted file itself sets at its end (`_fileDefaultsAtEnd(kept, ...)`: run
   `_processLine` over the `#_defaults_#` lines of `kept` alone, starting from no defaults, at `diffWidth`, not strict,
   and take the resulting defaults list), append one `#_defaults_#` line of memory's defaults, last, after every row:
   it persists the store's defaults for rows appended later, as 3.39's rewrite did, and changes how no row in the file
   reads. Compare the two lists with their trailing empty cells dropped.
8. Return `(None, _CompactRows(kept, values, tail), queued)`, where `_CompactRows` is `_RewriteRows(first=kept,
   values=values, ..., tail=deletionLines + defaultsLine)` with `whole = True`. `_RewriteRows` gets a `tail=()`
   argument (lines written after every row) and a class attribute `whole = False`. `check()` covers `values`, so a
   row memory must write and cannot encode refuses before anything is written, as in 5.4.

`_writeFileStarted`: `whole = whole or getattr(lines, 'whole', False)`. A compaction is always written whole
(`_writeLines` then `truncate`), never through `_writeInPlace`, which pads a shorter line with spaces and would change
the bytes of a kept line. Everything else in `_writeFileStarted` (the sync, the `_changedSince` retry, `_known`, the
failure paths, the queue put back) is unchanged; the retry loop calls `_snapshotForRewrite` again, which reads the file
again.

`_LinesFile(lines)`: `readline()` (next line + `b'\n'`, `b''` at the end), `__iter__`/`__next__` (the same), `tell()`
(bytes handed over so far). About 15 lines. No `io.BytesIO(b''.join(...))`: that would hold a second copy of the file.

`self._dumpNext` (the prototype's `_reordered`): set by `move_to_end` (legacy) and by Task 5b; cleared in
`_rewritten()` after a write that went through.

### Memory peak of the hybrid (the "second parse" question)

The second parse is streamed: it holds one flag per key (`_TSVZedDiff.flags`), not the rows, and the compaction holds
one small record per live key plus the raw lines (the file's bytes, which a whole rewrite must hold to write). Peak
during a compacting rewrite = raw lines + max(compaction records, diff flags) + the `_RewriteRows` snapshot of the diff
rows (usually few). Free the compaction state (`live`, `info`, `killer`) before step 4: `_legacyCompact` returns only
`kept`. If the measured slope in Task 5's test is above the bound there, slim the per-key record (store the four
indexes in `array('l')` columns with a key -> slot dict instead of a list per key).

The existing test `test_tsvzed_legacy_rewrite_memory_does_not_grow_with_the_store` stays as it is and must pass
unchanged: its file holds only the header, so every row is a diff row and goes through the same flat `_RewriteRows`
snapshot as 5.4 (protoH failed it because it encoded every diff row up front into a list). Task 5 adds the
healthy-file case.

## Changes from the prototype (protoH), all deliberate

- One read in the scrub (`_RawTap`), not a view read plus a raw read.
- No decoded copy of the file (`texts`) and no per-line tuple list in the compaction; per-key records instead.
- The emptied protected line is built from the line's own bytes (protoH encoded `[key] + ['']...`, which could raise
  `TSVZEncodeError` and re-encoded the key); not for `.nsv`.
- `lonesAreRows` parameter dropped (never set).
- Diff parse streamed (`_TSVZedDiff` flags, `_LinesFile`), diff rows through `_RewriteRows` (lazy encoding, `check()`),
  not a list of encoded rows and not a `held` copy of memory.
- `_shapeRow(load=True)` applies no defaults (protoH still filled them, which left the 1-column `#_defaults_#` mismatch).
- The scrub always writes (protoH skipped an unchanged file).
- `_compactSnapshot` also falls back to the dump on `_remake` and on damage met by its own read; the raw read goes
  through `_openStreams` on the locked descriptor (5.4's member reader).
- Defaults persisted at the end (step 7), pending Q2.
- Q-D5 uses `_givenDefaults`, which `setDefaults()` updates (protoH used `_constructorDefaults`, which it does not).

## Running things (all capped; copy these)

Before every container start, check the budget (all caps + the new one <= 48 GB, MemAvailable - new >= 8 GB, at most 8
of ours at once). Never loop waiting; if it says WAIT, try again later.

```bash
WT=/mnt/optane/work/cas/.worktrees/tsvz-55-width
budget() {  # budget <GB of the container about to start>
  caps=$(docker ps -q | xargs -r docker inspect -f '{{.HostConfig.Memory}}' | awk '{s+=$1} END {print s/2^30}')
  avail=$(awk '/MemAvailable/{print $2/1048576}' /proc/meminfo)
  ours=$(docker ps -q --filter label=tsvz55 | wc -l)
  awk -v c="${caps:-0}" -v a="$avail" -v n="$1" -v o="$ours" \
```
